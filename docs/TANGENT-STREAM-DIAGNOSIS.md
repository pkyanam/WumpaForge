# Original reflection tangent stream

Story16/build56 reaches real hub movement and then rejects required inputs v4/v5
of the 31-instruction reflection vertex shader. Stream1 is explicitly NULL with
stride24; stream0 is a 73728-byte pooled buffer (2048 records ×36 bytes), reference
count6. This is not the earlier zero-weight morph case: these tangent inputs are
live. No fallback values or bounds relaxation are justified.

Evidence is the supplied XBE's original disassembly in
`local/reports/disasm/asm/text.asm` and the ignored original-state captures
`story-16-shader.json`, `story-16-audio.json`, and `story-16.log`.

## Producer and consumer

- Shader1B's B7040 dispatch target is B8348 (two-level byte/DWORD jump table).
  B8454 calls39760 with geometry+1C, the game's one-based VB handle. B8461 binds
  the returned tangent buffer on stream1, stride24. 39760 reads
  `1E8D88+(handle-1)*32`; zero is the actual game lookup result.
- Original registry base1E8D78 has7000 records of32 bytes. 39670 initializes
  0xDAC0 DWORDs. Native primary VB is record+12, tangent VB record+16.
- Original pool base1E3E90 has1000 records of20 bytes. 3A550 uses fields
  `[game_handle, unknown, remaining_vertices, vertex_format, tangent_requested]`.
  Pools only match when the requested tangent flag matches exactly. New pools
  allocate at least2048 vertices. A nonzero fourth argument allocates24 bytes per
  vertex via3A450. The current primary size proves this pool route was used.
- AF0A0 reads an original serialized tangent-present DWORD. It selects9A1E0
  (pool flag1) or9A1A0 (flag0), loads36-byte primary vertices and conditionally
  loads24-byte tangent records. Inspection found no mismatch in this generated
  branch relative to original instructions.
- Tangents may also be generated by original9A860: it allocates via3A450, locks
  the actual buffer, offsets by geometry+20 ×24, and computes tangent records
  from original mesh vertices/indices. Scene/model loading invokes it when
  B63F0's selected shader has a nonzero manager flag queried through B7030.
  The reflection shader1B is registered atB6F63..B6F7A with this flag1.
- B8690 repeats this generation over scene instances following material/shader
  changes. The script callback49010 calls it when B7030 requests tangents.
  These original producer routes need investigation before treating a null
  binding as an intended GPU retention behavior.

## Bounded next capture

`tools/buffer_probe.py` reads the original registry and pools in a stopped process,
emitting registry entries matching currently bound native handles, all active pool
records, and matching geometry/material records reached through the original
B8690 scene traversal at23C2E0. It also records shader1B's manager fields.
It does not call guest or native game functions, alter memory, or continue threads.

```text
command script import tools/buffer_probe.py
script buffer_probe.dump(lldb.debugger, 'local/reports/story-17-buffers.json')
```

Validation so far: Python syntax check only; first stopped-process capture is
pending. The desired distinction is a pool created without tangents, allocation
failure/lifetime corruption, or a missed original tangent-generation path. No
renderer behavior has been changed for this boundary.
